# Git 速查（初学者版）

> 只记这一页就够用。
> **不要**去学 git-flow（`develop` / `release` / `hotfix` 那一套）—— 个人机器人项目用不上。

---

## 一、每天就这 5 条命令

| 命令 | 什么时候用 |
| --- | --- |
| `git status` | 随时。看"我改了哪些文件" |
| `git diff` | **提交前必做**。看"我到底改了什么" ⭐ |
| `git add <文件>` | 确认无误后，把文件放进暂存区 |
| `git commit -m "feat(vision): xxx"` | 存一个档 |
| `git log --oneline -10` | 看最近的存档 |

**最容易忽略的是 `git diff`。** 提交前扫一眼，能挡掉 90% 的"我什么时候改了这个？"

---

## 二、提交粒度的黄金标准

> **能编译通过 ＋ 只做了一件事 ＝ 一次提交**

✅ 好的例子

```
feat(vision): 新增视觉目标帧解析与超时保护
chore(cubemx): 使能 UART7 中断
fix(bsp): 修复串口缓冲满时丢字节的问题
```

❌ 坏的例子

```
更新            ← 信息量为 0，三个月后你完全不知道改了什么
改了一下
111
一次提交里混了 5 个不相关功能   ← 出问题没法只回滚其中一个
```

**判断方法**：`type(scope)` 你能一句话说清吗？说不清就说明该拆成两次提交。

**宁可提交得碎，也不要存一个 500 行的存档。** 提交是"存档点"，不是"成果汇报"。

## 三、做实验：开分支

个人项目**只需要 `main` 一条主线**。想做大改动、心里没底时，开个分支：

```powershell
git switch -c feat/chassis-pid     # 开分支做实验
# ...随便改、随便提交，搞坏了也不影响 main...

git switch main                    # 实验失败？切回主线
git branch -D feat/chassis-pid     # 删掉分支，世界清静
```

实验成功就合并：

```powershell
git switch main
git merge feat/chassis-pid
```

## 四、出事了怎么办（三条救命命令）

| 情况 | 命令 | 说明 |
| --- | --- | --- |
| 改乱了，**未提交**的改动全部还原 | `git restore .` | ⚠️ 不可恢复，先 `git diff` 看一眼 |
| 想临时存一下，去改别的 | `git stash` → `git stash pop` | 暂存 → 取出 |
| **已提交**的改动要撤销 | `git revert <commit>` | 安全，会生成一笔反向提交 |

> **永远不要用 `git reset --hard`** —— 它会真的把代码删掉。
> 万一误用了，`git reflog` 还能救回来，但别指望它。

## 五、⭐ 这个项目专属：CubeMX 的保护动作

**每次在 CubeMX 里点 "Generate Code" 之前，先提交一次存档：**

```powershell
git add -A
git commit -m "chore(cubemx): 配置前存档"
```

原因：CubeMX 会覆盖 `Core/` 下的文件。一旦生成错了（比如把 `huart7` 搞丢），
`git restore .` 就能一键退回。

另外一定要记住这条：**Generate Code 之后，如果 VS Code 里 `main.c` 还有未保存的旧缓冲区，
先选 "Revert File"**，否则你保存旧内容会把新生成的代码覆盖掉。

## 六、什么时候该提交

- ✅ 写完一个功能点、**编译通过** → 提交
- ✅ 改 CubeMX 配置的**前后各一次** → 提交
- ✅ 准备做有风险的改动（大重构、换库）→ 先提交
- ❌ 一天结束才提交一次 ← 等于没存档

## 七、能力优先级（别搞反）

很多人一上来纠结目录结构，却不会看 `git diff`。按这个顺序练：

1. **提交粒度** —— 能回滚到任何一个工作状态
2. **分支基本操作** —— 开分支做实验，好了合并，坏了删掉
3. **看懂 `git status` / `git diff` / `git log`**
4. 目录分层规范
5. Commit message 规范

前 3 条是"保命"的，后 2 条是"锦上添花"的。
